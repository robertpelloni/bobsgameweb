### 1. Vision and Engine Goals
*   **Ultimate Goal:** Restore and evolve the legacy Java engine (v8830) into a high-performance, modern TypeScript/PixiJS engine ("Omni-Engine").
*   **Target Platforms:** Seamless execution across Web, Desktop (Electron), and Mobile (Capacitor).
*   **Design Philosophy:** Bridge retro charm with modern responsiveness; achieve 1:1 legacy engine parity before expanding into Phase 3 (Modernization - WebGPU) and Phase 4 (Expansion - Multiplayer/Mobile).

### 2. Architecture & Design Patterns
*   **Entity Component System (ECS):** Centralized logic in `src/renderer/engine/ecs/`. Modular components handle state (`Transform`, `Sprite`, `Particle`, `Combat`, `Quest`, `Inventory`, `Weather`, `Light`), and specialized Systems handle logic loops (`Render`, `Behavior`, `Pathfinding`, `Weather`, `Particle`, `Lighting`).
*   **Unified Graphics Engine:** A centralized particle system (`ParticleEmitter` and `ParticlePresets`) is shared between the ECS layer and standalone scene renderers (e.g., `WeatherRenderer`). It supports complex physics, interpolation (size/color/alpha), and custom shapes.
*   **Advanced Entity Layer:** Hierarchy starting with `BaseEntity` provides 8-directional movement, 64-frame animation support, and Java-accurate turning behavior (turning through intermediate diagonals).
*   **Environment-Aware Audio:** `AudioManager` uses Howler.js for SFX/Music and `chiptune3` for legacy Tracker formats. It includes an environment-aware strategy (`PerformanceManager`) to prioritize compressed OGG assets on low-end/mobile hardware.

### 3. Key Engine Subsystems
*   **Legacy Ingestion Pipeline:** `LegacyMapLoader` and `TilesetBuilder` automate the import of extracted Java binary data, including connected room graphs and dialogue scripts.
*   **AI Asset Pipeline:** `GenerativeAIManager` facilitates text-to-asset generation, integrated directly into editors for automated loading, scaling (128x128), and quantization.
*   **Collision & Depth:** Metadata-driven hitboxes (30px adults, 24px children) with depth-sorting based on character collision points (`y - 2` for standard sprites).

### 4. Technical Decisions & Patterns
*   **Submodule Sanitization:** Redundant reference submodules (Aseprite, GrafX2, Tiled) are proactively removed from the git index in favor of native TS implementations (`AsepriteParser.ts`, `Palette.ts`, `MapData.ts`) to reduce technical debt.
*   **Multiplayer Security:** The WebSocket server (`server/index.js`) enforces per-socket rate-limiting (60fps for frames, 2/sec for chat) and sanitizes all incoming payloads (HTML stripping, coordinate validation).
*   **Version Governance:** Versioning is centralized in `VERSION.md` and synchronized across all project metadata and UI displays.

### 5. Development & Verification Workflow
*   **Continuous Autonomy:** Principal directive of autonomous agent execution with frequent commits and version bumps.
*   **Strict Verification:** A mandatory 100% pass rate on the 32+ integration tests in `src/__tests__` is required before any major feature submission.
*   **Environmental Adaptation:** Sandbox constraints (like dependency failures) are mitigated by using local static servers and Playwright for visual verification.

### **Overview: `bobsgameweb` (okgame)**
`okgame` is a high-performance TypeScript/PIXI.js reimplementation of the "bob's game" engine. It bridges retro 2D pixel art with modern web technologies (WebGPU, Wasm, AI). The project is in **Phase 4 (Expansion)**, focusing on regional clustering, performance scaling, and mobile optimization.

### **1. Core Architectural Patterns**
*   **Entity Component System (ECS):** Logic is decoupled from data. Systems (e.g., `RenderSystem`, `Physics`, `BehaviorSystem`) process entities based on their `Components` (e.g., `Transform`, `Sprite`, `Combat`).
*   **Scene Graph Management:** Managed via a `StateManager` scene stack. Key scenes: `WorldScene`, `BattleScene`, and editors (`WorldEditor`, `SpriteEditorScene`).
*   **State Machine Interaction:** Interaction flow is managed through an `interactionMode` state machine ('normal', 'dialogue', 'chat_choice', 'chatting') to handle multi-modal inputs.

### **2. Rendering & Graphics (PIXI.js v8)**
*   **Dual-Pipeline:** Automatic WebGL/WebGPU selection.
*   **WebGPU Compute Particles:** 100k+ particles driven by WGSL compute shaders and rendered via direct storage buffers.
*   **HQ2X Upscaling:** Real-time edge-aware upscaling for legacy sprites and assets.
*   **Depth Sorting:** uses `hitBoxFromTop` metadata (30px adults/24px kids) for accurate layering.

### **3. Performance & Scaling**
*   **Spatial Grid Broad-phase:** 128px spatial grid in `Physics.ts` ensures $O(N)$ collision performance.
*   **Wasm Physics Bridge:** C++ narrow-phase backend (`cpp_port/`) handles AABB and **batch collision** checks via WebAssembly, supporting 500+ entities at 60FPS.
*   **MMO Scaling:** Spatial partitioning via map-specific Socket.io rooms and `pako` (zlib) binary compression for large world sync packets.
*   **Client Interpolation:** Exponential decay lerping (`1.0 - Math.exp(-15 * dt)`) eliminates movement jitter for remote players.

### **4. AI Integration**
*   **Generative Pipeline:** Real-time generation of sprites, tilesets, and dialogue via OpenAI proxy (`server/ai_proxy.js`).
*   **NPC Chat:** Persisted conversational history and persona/mood metadata integration.

### **5. Build & Environment**
*   **Submodule Assimilation:** Logic from 31 redundant submodules ported to native TypeScript to minimize technical debt.
*   **Hardware Preference:** Options menu toggles for WebGPU and HQ2X preferences.
*   **Unified Update:** `updateEntity(dt, dx, dy, sprinting)` is the standard entry point for all living entities.

### **Project Architecture & Design Summary**

`bobsgameweb` (okgame) is a high-performance, hybrid-engine implementation of the "bob's game" universe. It is built to bridge the gap between retro 2D pixel art and modern web capabilities, supporting massive regional clustering (MMO) and compute-heavy visual effects.

#### **1. Core Architectural Pillars**
*   **Entity Component System (ECS):** The engine uses a custom ECS (`src/renderer/engine/ecs/`) to decouple game data from logic. Systems such as `Physics`, `RenderSystem`, and `BehaviorSystem` operate on entities with specific component signatures (e.g., `TransformComponent`, `SpriteComponent`).
*   **Scene Management:** Managed by a `StateManager` stack. Each scene (e.g., `WorldScene`, `BattleScene`, `VisualizerScene`) is an isolated environment with its own update/render lifecycle.
*   **State Machine Interaction:** Interaction logic in `WorldScene.ts` follows a dedicated state machine (`normal`, `dialogue`, `chat_choice`, `chatting`). This prevents overlapping input listeners and manages the transition between static legacy dialogue and dynamic AI chat.

#### **2. Rendering & Graphics**
*   **PIXI.js v8 Integration:** Uses a dual-pipeline renderer that prefers WebGPU for modern hardware while maintaining a WebGL fallback.
*   **Compute-Driven Particles:** The `WebGPUParticleSystem` uses WGSL compute shaders to simulate 100k+ particles directly on the GPU, feeding into a vertex shader for high-performance rendering.
*   **HQ2X Upscaling:** Real-time, edge-aware upscaling is available for legacy assets, ensuring they look sharp on high-DPI displays without losing pixel art integrity.
*   **Metadata-Driven Sorting:** Living entities are Y-sorted using legacy hit-box offsets (30px for adults, 24px for children) to ensure 1:1 visual parity with the original game.

#### **3. Performance & Multiplayer Scaling**
*   **Spatial Partitioning:** The world is divided into map-specific Socket.io rooms to minimize broadcast noise.
*   **Wasm Physics Bridge:** Narrow-phase collision detection and batch array processing are offloaded to a C++ backend (`cpp_port/`) via WebAssembly, achieving $O(N)$ efficiency.
*   **Network Optimization:** Uses `pako` (zlib) for binary compression of synchronization packets and exponential decay interpolation to eliminate movement jitter for remote players.

#### **4. AI-Driven Ecosystem**
*   **Generative Pipeline:** Integrated `GenerativeAIManager` facilitates text-to-sprite and text-to-dialogue generation, allowing for dynamic NPC and asset creation directly within the `WorldEditor`.
*   **Conversational NPCs:** NPCs support persistent chat history and are characterized by `persona` and `mood` metadata stored in the `RPGDatabase`.

#### **5. Mobile & UX Refinement**
*   **Mobile-First Controls:** The `TouchControls` system mimics a handheld console with a virtual analog joystick and dedicated action buttons (A, B, E, INV, QST, RUN).
*   **Haptic Integration:** Tactile feedback is integrated into all virtual interactions via the `navigator.vibrate` API, with user-configurable intensity.
